# ReviewStage — UX and visual design audit

Audited 09/18/26 against `claude-pr-review-bot` `main` @ `4cb5d70`, read-only. Evidence lives in three folders next to this file: `app/` (the supplied 42 app shots), `site/` (the supplied 12 website shots), and `new/` (63 shots I took of states the supplied set does not cover: sign-in idle / device-code / denied / PAT-only, running, merged, stale + head-moved, editing, request-changes, after-post, Explain loading and done, ⌘K, tour, help menu, queue filter / empty / new-install / running-only, QA none and failed-with-existing, Skills with editors open, stack page, Insights 7d, Settings with a minted token, and keyboard-focus probes). `crops/` holds the landing page sliced into readable strips. All contrast figures below are computed WCAG 2.x ratios from the hex values in `dashboard-ui/src/styles.css:1-12`, with translucent pill backgrounds blended onto their real panel colour.

## Verdict

ReviewStage has the right idea and the right words, and almost none of the visual system needed to carry them. The one concept the product exists for — a private stage where findings wait for a human — is never drawn: on the PR page the stage is one more bordered card in a column of twelve identical bordered cards, so the eye lands on a dry-run banner and a yellow emoji rather than on the findings and the Post button. The app's navy-and-indigo dark theme, the website's cream-and-orange, and the brand mark's ink-and-electric-blue are three unrelated identities; the app has no light theme at all while the website ships one. Beneath the surface, the interaction layer is mostly sound (states are named, errors are sentences, nothing posts on Enter) but a specificity mistake removes every keyboard focus ring on links, buttons and disclosure summaries, the phone header is seven unlabelled 30 px icons, and roughly a third of the reading text sits below WCAG AA. The copy is the strongest asset in the codebase and should survive the redesign untouched; the chrome around it should not.

## What is already right (keep it)

- **The copy.** Plain, active, honest, specific: "Nothing reaches GitHub without your click", "Your queue is empty because this install isn't ready yet, not because you're caught up", "Approving would bless commits nobody here has read", the phishing warning on the device code. Error messages are sentences the user can act on, not codes. Every empty state has a title, an explanation and a next step. Preserve these strings verbatim.
- **The safety model in the interaction layer.** Findings and Approve are deliberately not `<form>`s so Enter never posts (`PrPage.tsx:795-797, 916-918`); approving a moved branch requires a typed acknowledgement; a replaced run refuses to post and says why; a 502 re-enables the button and shows the server's words. This is the product's promise implemented correctly.
- **Server-driven state vocabulary.** Every state (new / reviewing / done / posted / approved / archived / failed / stalled / stopped / queued) has a name, a pill and a page treatment; the running pill in the sidebar links straight to the one running job.
- **Finding card content structure.** Title → "Why it matters" → collapsed technical body → optional suggestion block → "Explain simply" is the right order for a human deciding from prose.
- **Command palette.** Fast, keyboard-first, groups PR lookup with navigation, shows the shortcut in the button.
- **Reduced motion** is honoured globally; the running dot and palette entrance have explicit opt-outs.
- **Sign-in device flow** covers idle / starting / waiting / denied / expired / network-blip / 429 with distinct copy and a Cancel that releases the server slot.
- **Website type and rhythm at the section level** — Outfit display sizes via `clamp()`, generous section padding, a real light/dark/auto toggle — are a good base; the problem is quantity, not quality.
- **The mark** is distinctive and legible at 28 px.

## The five changes that would matter most

1. **Draw the staging area.** Make the findings list the single elevated surface on the PR page, with a sticky bottom bar ("2 of 3 selected · Post as acme-dev") that transitions in place to a posted state.
